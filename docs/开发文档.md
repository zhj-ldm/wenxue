# 问学 · 开发文档

> 一句话定位：**一个装在本机的 AI 出题 + AI 教学桌面应用**。所有学习内容统一为「载体」（试卷 / 练习 / 提升计划），本地 JSON 保存；AI 通过内置 pi Agent 直接读写载体、出题、批改、讲解，并可用内置 Aggr Search 联网。

---

## 1. 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 桌面壳 | Electron 45 + Node 22 | macOS / Windows，自绘顶栏，无系统原生标题栏 |
| 前端 | 原生 HTML + CSS + ES Module | 无框架、无打包器，改完刷新即可 |
| 主进程 | CommonJS | IPC 白名单，`contextIsolation: true`、`nodeIntegration: false` |
| AI | `@earendil-works/pi-ai` + `pi-agent-core`（MIT） | 全部模型请求在主进程内完成，不依赖任何外部 CLI |
| 联网搜索 | Aggr Search（`bin/aggrsearch`，Rust） | 多引擎聚合，AI 通过 `web_search` / `web_fetch` 调用 |
| 打包 | `scripts/build-app.sh`（macOS）、electron-builder（Windows） | GitHub Actions 出 EXE |

历史版本曾使用 OpenCode CLI，现已完全移除。

## 3. 数据目录

默认 `~/Library/Application Support/Wenxue/data/users/local/`（Windows 为 `%APPDATA%/Wenxue/...`）：

```
settings.json                       学习偏好、当前接口、放题目录
profiles.json                       API 接口（地址 / Key / 模型）
conversations.json                  「对话」页的 AI 会话
carriers/<CODE>/carrier.json        载体（试卷 / 练习 / 提升计划）
carriers/<CODE>/attempts/<id>/attempt.json   作答、批改、进度
carriers/<CODE>/attempts/<id>/chats/<qid>.jsonl  单题会话（与题一一绑定）
carriers/<CODE>/global-chat.jsonl   整套 AI 对话
migrated-carriers-v2.json           旧数据迁移标记
```

放题目录（默认 `~/Documents/问学试卷`）用于放入/导出载体 JSON，按学科分子文件夹；启动与手动同步时自动识别未收录的文件。导入时会记录源文件路径，在应用内删除载体时会一并删除该源 JSON，避免重启后再次导入。旧版 `papers/`、`plans.json`、`tasks/` 只在首次启动迁移时读取，迁移完成后不再写入。

所有 JSON 采用「临时文件 + 原子重命名」写入，并在覆盖前保留 `.bak` 备份；读取失败时自动回退到备份，避免异常退出导致整份会话或作答丢失。

## 4. 载体模型

### 4.1 三种类型

| `kind` | 含义 | 组织方式 |
| --- | --- | --- |
| `paper` | 整套试卷 | 按大题分区，模拟正式考试 |
| `practice` | 专项练习 | 零散题目，可只有一个大题 |
| `plan` | 提升计划 | 每天一个 section，`section.date` 排期 |

```json
{
  "schemaVersion": 2,
  "code": "A7K2M9Q1",
  "kind": "paper",
  "title": "高一语文·散文阅读",
  "subject": "语文",
  "grade": "高一",
  "goal": "",
  "difficulty": 3,
  "totalScore": 20,
  "durationMinutes": 25,
  "instructions": "阅读下面的散文，完成下列小题。",
  "sections": [
    {
      "name": "一、现代文阅读",
      "passage": "共用材料全文……",
      "date": "2026-11-20",
      "questions": [
        {
          "id": "q1",
          "type": "choice",
          "layout": "block",
          "stem": "……",
          "passage": "",
          "blanks": [],
          "options": [{ "key": "A", "text": "……" }],
          "maxScore": 3,
          "referenceAnswer": "B",
          "rubric": [{ "point": "选对", "score": 3 }],
          "knowledgePoints": ["散文阅读"],
          "difficulty": 2,
          "date": "",
          "answerMode": "fixed",
          "actions": { "grade": true, "explain": true, "chat": true }
        }
      ]
    }
  ]
}
```

### 4.2 编号

每个载体在保存时自动生成 **8 位编号**（字母表 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`，`crypto.randomInt` 生成并去重）。首页卡片、载体页头部、整套对话入口都会展示编号；点击即可复制。AI 可用 `find_carrier` 按编号检索。

### 4.3 日期与每日任务

- 题目生效日期 = `question.date || section.date`。
- 到期（日期 ≤ 今天）且未作答的题进入「每日任务 → 待完成」；作答后自动移到「已完成」，待办卡片不再出现。
- 每日任务只显示载体卡片（标题、编号、题数、进度），点击进入载体页并自动滚动定位到第一道待做题；支持提前作答与回看历史。
- 完成后不会删除作答记录，仍可在载体页与「记录」页查看。

### 4.4 出题端可配置项

- `actions`：`{grade, explain, chat}`，任一为 `false` 时隐藏该题对应按钮；三个按钮都唤起右侧同一侧边栏。
- `answerMode`：`fixed` 有标准答案；`open` 表示「答案不唯一」，不设标准答案，由 AI 读取学生作答后判分。
- 选择题 / 填空题可预设 `referenceAnswer`；`open` 模式可只写评分要点。

### 4.5 内联填空（题文与答案穿插）

填空题默认内联：`layout: "inline"`，在 `passage` 或 `stem` 里用 `{{1}}`、`{{2}}` 标出空位，`blanks` 给出每个空的 `key / answer / maxScore`。

```json
{
  "id": "q7",
  "type": "fill_blank",
  "layout": "inline",
  "stem": "The Great Wall {{1}} (build) long ago, and it {{2}} (visit) by many people every year.",
  "blanks": [
    { "key": "1", "answer": "was built", "maxScore": 1 },
    { "key": "2", "answer": "is visited", "maxScore": 1 }
  ],
  "maxScore": 2,
  "referenceAnswer": "1. was built  2. is visited",
  "rubric": [{ "point": "时态与语态", "score": 2 }]
}
```

- `{{n}}` 与 `blanks[].key` 必须一一对应；没有标记但有 `blanks` 时依次追加在题干末尾。
- 每个空的值同时写入 `answers[qid].blanks` 与可读文本 `answers[qid].answer`，批改与 AI 都读后者。
- `layout` 缺省为 `block`，即「题干 + 下方答案区」。

## 5. AI 层

### 5.1 模型归一

模型只在「设置 → API 接口」配置，支持多接口切换。所有功能——批改、讲解、单题对话、整套对话、全局 Agent——统一读取 `store.activeProfile()` 的 `baseUrl / apiKey / model`，页面不再出现按试卷选模型的下拉框。应用层不限制输出长度，`maxTokens` 跟随上下文窗口，实际上限由模型与接口商决定。

### 5.2 pi Agent

`electron/lib/pi.js`：

- `startAgent`：按 `sessionId` 复用 Agent；复用时可热更新 `thinkingLevel`。
- `runAgent`：订阅 `message_update`（`text_delta` / `thinking_delta` / `thinking_end`）、`tool_execution_start/end`、`agent_end`，转成前端事件。
- `completeText`：批改用的一次性补全。
- `cancel(runId)`：中止当前 Agent；`resetSession` 清空会话。

思考强度 `off / low / medium / high` 由侧边栏与对话页下拉决定；模型不支持 reasoning 时不产生思考输出，其余功能正常。

### 5.3 会话隔离

| 场景 | 存储 | 上下文 |
| --- | --- | --- |
| 单题对话 / 批改 / 讲解 | `attempts/<id>/chats/<qid>.jsonl` | 本题作答 + 所属大题；开关打开后可读整套 |
| 整套对话 | `carriers/<CODE>/global-chat.jsonl` | 整个载体的题目、作答、得分 |
| 对话页 | `conversations.json` | 全局学习助手，可调用全部载体工具 |

不同小题的会话完全隔离；切换题目时侧边栏加载对应历史。

## 6. 右侧 AI 侧边栏

- 题目下方只保留「批改 / 讲解 / AI 对话」三个按钮，任意一个都唤起右侧固定侧边栏。
- 顶部显示当前题与所属大题；「允许读取整套载体」开关默认关闭，关闭时 AI 只能读本题 + 所属大题（仍可联网搜索），打开后才授予 `find_carrier / list_carriers` 等整套工具。
- 底部输入框支持 `⌘/Ctrl + Enter` 发送；运行中显示「停止」，调用 `ai:cancel`。
- 思考、工具调用与正文按真实顺序分块，由 `renderer/agentflow.js` 渲染：思考收起为一行（含预览与耗时，可展开），工具卡显示运行中 / 完成 / 失败 / 已取消，展开可看参数与输出。
- 运行中在没有流式内容时显示阶段提示（正在思考 / 正在整理思路 / 正在调用工具 / 正在整理工具结果），停止后显示「已停止生成」，正在运行的工具标记为已取消。
- 每个载体底部有「整套 AI 对话」入口，上下文为整个载体，适合整套总结与错题分析。
- 主内容与侧边栏之间的分隔条可拖动调整宽度，宽度会记住。
- 页面左侧有批注悬浮球：展开后选颜色、拖动滑杆调笔画粗细，选中颜色即自动收起并开启书写；左键拖动写字，右键不响应，顶部 66px 导航区不可落笔。批注按所在滚动容器记录坐标，页面/侧边栏滚动时会跟着内容一起移动；批注层不拦截鼠标，按钮、选项与输入框优先响应，可边答题边批注；展开面板里可开关批注、撤销或清空。

## 7. 学习页三个选项卡

### 7.1 试卷练习

展示 `kind=paper` 与 `practice` 的载体卡片：类型、标题、8 位编号（可复制）、学科、题量、满分、作答进度。点击进入载体页。

### 7.2 每日任务

- 待完成 / 已完成两组，只显示载体卡片，不内嵌题目。
- 顶部日期栏支持前一天 / 后一天切换、直接选择或输入 `YYYY-MM-DD`，并可一键回到今天；角标始终显示今天的待完成数量。
- 点击卡片进入载体并自动定位到目标题，可提前作答与回看历史。
- 完成后自动从待完成移出。

### 7.3 提升计划

展示 `kind=plan` 的载体。计划内每天是一个带 `date` 的 section；到期题目自动进入每日任务，计划与每日任务是同一份数据。

## 8. Agent 工具

| 工具 | 作用 |
| --- | --- |
| `create_carrier` | 创建载体：`{kind,title,subject,grade,goal,instructions,durationMinutes,sections}` |
| `update_carrier` | 按编号局部更新载体 |
| `find_carrier` | 按 8 位编号或关键词检索 |
| `list_carriers` | 列出全部载体与进度 |
| `delete_carrier` | 按编号删除载体 |
| `read` / `write` / `edit` | 读写本地文件 |
| `bash` | 执行命令（超时、输出截断） |
| `web_search` | 内置 Aggr Search 多引擎搜索 |
| `web_fetch` | 抓取网页正文 |

题目字段与第 4 节一致（含 `date`、`actions`、`answerMode`、`layout`、`blanks`）。AI 一律通过工具写入，不手写文件。

### 8.1 内置 Aggr Search

- 可执行文件放在 `bin/aggrsearch`（Windows 为 `bin/aggrsearch.exe`），开发与打包都会带上。
- 调用方式：`aggrsearch search "<关键词>" --max 6 --json`、`aggrsearch fetch <url> --json`。
- 找不到内置文件时，可在「设置 → 联网搜索命令」填写自定义命令（支持 `{{query}}` 占位）覆盖。

## 9. IPC 一览

- 启动/设置：`app:bootstrap`、`settings:get|save`
- 接口：`provider:list|save|delete|activate|models|test`
- 文件：`dialog:pickFolder|pickFile`、`file:read`、`app:openExternal`
- 载体：`carrier:list|get|save|delete|import|answer|finish|daily|history|grade|qchat|gchat|syncFolder`
- 全局 Agent：`agent:chat`、`agent:conversations`、`agent:conversation:get|new|delete|rename`
- 取消：`ai:cancel`
- 提示词：`prompts:list`

所有通道在 `electron/preload.js` 白名单中显式列出，`contextIsolation` 开启。

## 10. 打包与发布

### macOS

```bash
./scripts/build-app.sh              # 产出 /Applications/问学.app
OUT_DIR=dist ./scripts/build-app.sh # 产出到项目内
```

脚本复制 Electron 模板与应用代码，`productName` 保持 `Wenxue` 以便与开发版共用数据目录，最后 ad-hoc 签名。

### Windows

`.github/workflows/build-windows.yml` 在打 `v*` tag 或手动触发时用 electron-builder 出 NSIS 安装包（x64），并附加到 Release。

> Windows 版若要联网搜索，需要把 Windows 平台的 `aggrsearch.exe` 放进 `bin/` 再打包；macOS 版仓库内已带 arm64 版本。

## 11. 安全

- API Key 只保存在本机用户数据目录，不写入仓库、不打印日志。
- 页面通过 preload 白名单调用主进程，渲染层无 Node 权限。
- 打包/发布前检查 `git status`，确保没有 `settings.json`、`.env` 或 Key 进入提交。

---

## 12. 已知限制

- 模型不支持 reasoning 时，思考面板不会出现，只有正文流式输出。
- 每日任务可按日期前后查看与直接输入日期；跨天数据以本机日期为准，打开页面时刷新。
- 应用层不限制输出长度，但模型/接口商自身仍有单次输出上限。
- 联网搜索依赖内置二进制，缺失时降级为自定义命令，再缺失则工具报错并提示。
- 旧版试卷/计划/任务在首次启动时迁移为载体，旧目录保留不删除，仅用于回滚。
