# 问学 · AI 试卷练习（开发文档）

> 版本：v1.0 · 2026-10-26
> 一句话定位：**一个只跑在 Electron 里的桌面刷题工具，后端完全依赖本机已安装的 OpenCode CLI 作为 Agent 引擎，按学科浏览/导入试卷、逐题作答、逐题 AI 批改与逐题独立对话，并内置一个完整的 Agent 对话页（出卷/答疑/规划），全流程可保存可回溯。**

---

## 1. 需求汇总（来自需求讨论）

| 编号 | 需求 | 落地方式 |
| --- | --- | --- |
| R1 | 后端不是"调某个模型"，而是**整个 Agent 方案就是 OpenCode CLI**，直接复用本机已安装的 CLI 与已登录账号 | 主进程以子进程方式调用 `opencode run --format json`，不接任何云端 SDK |
| R2 | 单用户本机应用：不做账号/登录，数据只有一份 | 固定 uid `local`，`data/users/local/` 下存试卷、进度、对话；旧版多账号数据首次启动自动合并 |
| R3 | 初始界面为**选试卷**，按学科分类 | 首页学科宫格 → 学科试卷库 → 试卷卡片 |
| R4 | 每套卷作答前**顶部可选模型**，来自本机 CLI 的可用模型列表 | 顶部 `Model` 下拉，数据来自 `opencode models`；可按卷保存 |
| R5 | 逐题作答 + **一键 AI 打分/出分**（分数、评语、失分点、知识点） | 每题 `Grade with AI` 按钮，走规范化评分提示词，输出严格 JSON |
| R6 | 每题**独立对话窗口**：只显示"我在该题下与 AI 的对话"，可回溯；同一套卷统一管理 | 每题独立 OpenCode session + 每题独立对话日志文件；UI 上对话窗口内嵌在题目卡片下方 |
| R7 | 上下文：整套卷统一管理，大题/单题上下文独立压缩 | 一题一会话，天然隔离；跨题只共享试卷概要（需要时由应用拼接） |
| R8 | AI **自主命题**并输出**特定格式**到**指定文件夹** | 不再做单独的命题表单：由主界面「AI 对话」里的 Agent 直接读写放题目录，格式约束写在首轮系统上下文里 |
| R9 | AI 去网上找题/找卷子 → 转成特定格式 | 同上，联网能力由本机 CLI 的 Agent 工具提供 |
| R10 | 提示词规范化（评分标准等） | `prompts/` 目录统一维护，变量占位符渲染；出卷格式契约打包进 `agent:chat` 的系统上下文 |
| R11 | 进度保存/退出续做、答题记录回看 | `attempts` 目录 + 自动保存（防抖 500ms） |
| R12 | 全学科支持，数学不推荐但可用 | 学科列表含数学，默认提示标注"建议手写" |
| R13 | 只做前端 Electron，不引复杂框架，尽量省磁盘 | 原生 HTML/CSS/ES Module，零前端依赖；仅 electron 一个 devDependency |

## 2. 技术选型

### 2.1 结论

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 壳 | Electron 45（Node 22） | 跨平台桌面、免装运行时 |
| UI | 原生 HTML + CSS + ES Module | 无打包器、无 React/Vite，`node_modules` 只有 electron |
| 主进程 | Node.js（CommonJS） | 负责存储、子进程调度、IPC |
| Agent | 本机 OpenCode CLI | 不新增云端依赖，账号/模型/工具全部复用 |
| 存储 | JSON 文件（原子写入） | 零原生模块、零编译、可迁移、可手工查看；单机题库规模足够 |
| 密钥 | `safeStorage`（可用时）加密后存盘 | 免明文落盘 |

> 为什么不用 SQLite：`better-sqlite3` 需为 Electron ABI 重新编译（约 +30MB 且易失败）；本项目为单机个人工具，数据量在千条量级，JSON + 分文件已足够，且更"省磁盘、可回溯"。

### 2.2 磁盘占用策略

- 生产代码本体 < 300KB；`node_modules` 仅 electron（约 250MB，安装后不可免）。
- 不做前端打包，不产出 dist 冗余。
- 对话日志按「题 × 作答」单独成文件，增量追加，避免单文件膨胀与整文件重写。
- 不复制试卷原文件到应用数据目录（只在题库登记路径/或存一份精简 JSON）。

## 3. 总体架构

```
┌──────────────────────────── Electron ────────────────────────────┐
│  Renderer (renderer/)                                            │
│    index.html + app.js + views/*.js + styles.css                 │
│        ↕ window.api（preload contextBridge，contextIsolation）    │
│  Main Process (electron/)                                        │
│    main.js       窗口 + IPC 路由 + 业务编排                        │
│    lib/store.js  设置 / 试卷库 / 作答 / 对话日志 / 放题目录扫描        │
│    lib/opencode.js  CLI 探测 / models / run 流式 / 取消 / 超时     │
│    lib/prompts.js  提示词加载与渲染                                │
│    lib/papers.js   试卷 Schema 归一化 / 校验 / 导出                │
│    lib/grader.js   评分 JSON 提取、容错、客观题本地判定             │
│        ↓ child_process.spawn                                     │
│    opencode CLI（本机安装，复用其登录态与模型）                     │
└──────────────────────────────────────────────────────────────────┘
        ↓
   本地数据目录（~/Library/Application Support/问学/data）
```

**关键约束**

1. 渲染进程不直接 `require`、不直连网络、不碰文件系统，全部经 IPC。
2. 所有 AI 输出都需经过解析/校验，解析失败时保留原文并降级展示，**不吞错**。
3. 子进程一律可取消、可超时，避免进程泄漏。

## 4. 数据模型与存储布局

### 4.1 目录

```
<userData>/data/
  settings/                      # 全局（CLI 路径、provider 密钥）
    global.json
  users/local/                   # 单用户，固定 uid = local
    settings.json                # 偏好：默认模型、放题目录、超时、自动批改
    papers/
      index.json                 # 试卷摘要列表（快速渲染，不含题目正文）
      <paperId>/
        paper.json               # 完整试卷（含题目、参考答案、评分细则）
        attempts/
          <attemptId>/
            attempt.json         # 作答记录：答案、批改结果、模型、时间
            chats/
              <questionId>.jsonl # 该题在该次作答下的对话（追加写）
```

放题目录（默认 `~/Documents/问学试卷/<学科>/<yyyyMMdd>-<标题>.json`）与应用数据目录互为镜像：写入是导出，读取是启动时自动扫描收录。

会话目录：`<userData>/workspace/local`，作为 CLI 的 cwd，保证会话归属同一 project，避免污染用户自己的代码仓库。

### 4.2 试卷 Schema（对外唯一格式）

> 完整字段说明、示例与硬性约束见 [paper_master.md](../prompts/paper_master.md)——单文件自包含，可直接投喂任意 AI 命题。

应用内部归一化后的试卷结构如下：

```json
{
  "schemaVersion": 1,
  "id": "paper_xxx",
  "title": "高一语文 · 现代文阅读专项",
  "subject": "语文",
  "grade": "高一",
  "source": "generated | imported | searched",
  "difficulty": 3,
  "totalScore": 100,
  "durationMinutes": 90,
  "instructions": "作答说明（可选）",
  "createdAt": "2026-10-26T12:00:00.000Z",
  "sections": [
    {
      "name": "一、现代文阅读",
      "passage": "本大题共用的阅读材料全文（无则为空字符串）",
      "questionIds": ["q1", "q2", "q3"]
    }
  ],
  "questions": [
    {
      "id": "q1",
      "section": "一、现代文阅读",
      "type": "short_answer",
      "stem": "请结合全文，分析作者的情感变化。",
      "passage": "",
      "options": [],
      "maxScore": 6,
      "referenceAnswer": "参考答案",
      "rubric": [{ "point": "答出情感由…转…", "score": 3 }],
      "knowledgePoints": ["散文阅读", "情感线索"],
      "difficulty": 3,
      "explanation": ""
    }
  ]
}
```

**要点**

- **大题-小题结构**：`sections` 描述大题分区与共用阅读材料，`questions` 是扁平小题数组；`questionIds` 把两者关联起来。
- **共用材料只放一次**：放在 `section.passage`，小题 `passage` 留空；渲染时大题材料展示一次，小题不重复。
- Agent 输出时只需给 `sections[].questions`（小题内嵌在大题里），应用归一化时会拍平成 `questions` + `sections[].questionIds`。
- `type` 取值：`choice`（单选）、`multi_choice`、`fill_blank`（填空）、`short_answer`（简答）、`essay`（作文/长文）、`translation`（文言/英译中）、`calculation`（可含公式的解答，数学/物理用）、`other`。

### 4.3 作答记录 Schema

```json
{
  "id": "att_xxx",
  "paperId": "paper_xxx",
  "userId": "u_xxx",
  "model": "opencode/big-pickle",
  "startedAt": "...",
  "updatedAt": "...",
  "finishedAt": null,
  "answers": {
    "q1": { "answer": "我的作答", "updatedAt": "..." }
  },
  "grades": {
    "q1": {
      "score": 4.5, "maxScore": 6, "level": "良好",
      "comment": "总评…",
      "highlights": ["…"], "issues": [{ "point": "…", "advice": "…", "deduct": 1.5 }],
      "knowledgePoints": ["…"], "nextSteps": ["…"],
      "gradedAt": "...", "model": "..."
    }
  },
  "chatSessions": { "q1": "ses_..." },
  "summary": { "total": 62.5, "max": 100 }
}
```

### 4.4 对话日志（JSONL，一行一条）

```json
{"role":"user","kind":"chat","content":"…","ts":1793020000000}
{"role":"assistant","kind":"chat","content":"…","ts":...,"model":"…","toolCalls":[{"tool":"bash","title":"…"}]}
{"role":"assistant","kind":"explain","content":"…","ts":...}
```

- `kind`：`chat`（自由问答）/`explain`（一键讲解）/`grade_note`（批改摘要入窗）。
- 每题一个文件：天然满足"该窗口只保留这道题的对话"。

## 5. OpenCode CLI 集成

### 5.1 已验证的 CLI 能力（本机 v2.1.4）

| 能力 | 命令 | 说明 |
| --- | --- | --- |
| 模型列表 | `opencode models` | 每行 `provider/model` |
| 一次性执行 + 事件流 | `opencode run --format json --auto -m <model> -s <sessionId> "<prompt>"` | 输出 JSONL 事件 |
| 会话续接 | `run -s <sessionId>` | 同 id 自动续接；不存在则创建 |
| 账号/凭据 | `opencode auth list / export` | 支持 `OLLAMA_API_KEY` 等环境变量注入 |

事件类型（实测）：`step_start`、`text`（part.text 为**整段**文本，非增量）、`tool_use`（part.type=tool，含 state/title）、`step_finish`、`error`。

> 结论：不启动常驻 `serve`（需密码鉴权、易残留进程），改用**每条消息拉起一次 `run` 子进程**。代价是文本不逐字流式，UI 用"思考中/生成中"状态 + 分段到达呈现，符合本项目"轻量、无守护进程"的取向。

### 5.2 CLI 路径探测顺序

1. 设置里手动指定的路径（`global.json.cliPath`）
2. 环境变量 `OPENCODE_BIN`
3. `~/.opencode/bin/opencode`
4. `~/Library/Application Support/ai.opencode.desktop/cli/*/*/opencode-cli`（macOS OpenCode 桌面版）
5. `~/.local/bin/opencode`、`/opt/homebrew/bin/opencode`、`/usr/local/bin/opencode`
6. `which opencode`（经登录 shell）
7. Windows：`%LOCALAPPDATA%\\Programs\\opencode\\opencode.exe`、`%APPDATA%\\npm\\opencode.cmd`

探测成功后展示版本（`--version`），供设置页"测试连接"。

### 5.3 凭据注入

- 应用内"Provider 账号"可保存 API Key（`safeStorage` 加密）。
- 调用 CLI 时合并入子进程环境变量，映射关系：
  `ollama-cloud → OLLAMA_API_KEY`、`openai → OPENAI_API_KEY`、`anthropic → ANTHROPIC_API_KEY`、`openrouter → OPENROUTER_API_KEY`、`deepseek → DEEPSEEK_API_KEY`、`google → GOOGLE_GENERATIVE_AI_API_KEY`、`groq → GROQ_API_KEY`、`mistral → MISTRAL_API_KEY`、`xai → XAI_API_KEY`。
- 未配置时直接继承系统环境与 CLI 自身登录态（`opencode auth`）。
- 错误事件统一翻译成中文提示：`provider.free-limit`（额度用尽）、`provider.auth`（401 / 地区限制）、`timeout`。

### 5.4 会话策略

| 场景 | session | 理由 |
| --- | --- | --- |
| 单题对话 | 每题一个稳定 id（`ses_<uid8><paper6><qid><att6>`） | 一题一窗、上下文独立、可续接 |
| 一键讲解 | 复用该题的对话 session | 讲解内容出现在该题窗口，可继续追问 |
| AI 批改 | **不建会话**（一次性） | 评分必须自包含、可复现，不污染对话上下文 |
| AI 对话（全局 Agent） | 首次不传 session，用 CLI 返回的 session id 续接；「新对话」清空 | 多轮连续、可随时重开 |
| 导入试卷 | 不走 AI（纯本地 JSON 解析） | 快、稳、不耗额度 |

### 5.5 超时与取消

- 默认超时 180s（设置可调 30–600s）；`SIGTERM` → 3s 后 `SIGKILL`。
- 每个运行实例持有 `runId`，UI 可 `Cancel`；窗口关闭/切换用户时统一清理。

## 6. 提示词规范（`prompts/`）

所有提示词文件均为 Markdown，变量占位 `{{name}}`，由 `lib/prompts.js` 渲染。

| 文件 | 用途 | 输出契约 |
| --- | --- | --- |
| `grade.md` | 单题批改 | **纯 JSON**（评分对象），禁止多余文字 |
| `explain.md` | 一键讲解（错因 + 思路 + 知识点） | Markdown 讲解 |
| `question_context.md` | 题目上下文（拼接在每题首条消息前） | 文本 |
| `paper_master.md` | **命题总指令（单文件自包含）**：自主命题 + 联网找题 + 试卷格式规范全部合并，可直接投喂任意 AI | 纯 JSON（试卷 Schema） |

**评分 JSON 契约**

```json
{
  "score": 4.5,
  "level": "优秀|良好|合格|待提高",
  "comment": "总评（≤120字）",
  "highlights": ["得分点"],
  "issues": [{ "point": "失分点", "advice": "改进建议", "deduct": 1.5 }],
  "knowledgePoints": ["知识点"],
  "nextSteps": ["可执行的下一步"]
}
```

统一硬性规则（写入每个提示词头部）：

- 只依据题目、参考答案、评分细则评分，**不得臆造题外标准**；
- 分值不得超过 `maxScore`，各 `deduct` 之和应与 `maxScore - score` 基本一致；
- 输出 JSON 时不加代码块围栏、不加解释、不加前后缀；
- 若信息不足，`comment` 中明确指出"以参考答案为准"，仍给出分数。

**解析容错（lib/grader.js）**：先直接 `JSON.parse`；失败则剥离 ```json 围栏；再失败则括号配平截取首个对象；仍失败则降级为"纯文本评语 + score=null"，并在 UI 标注"结构化失败，已保留原文"。

## 7. 界面与流程

### 7.1 视觉

- 纸张质感暖色底（`#F6F3ED`）+ 象牙面板（`#FFFDF9`），墨色正文，深松绿主色（`#2F5D50`），陶土橙点缀分数/警示。
- 标题用衬线（Songti SC / Noto Serif SC），界面用无衬线（PingFang SC）。
- 操作按钮统一 **英文**（Grade with AI / Explain / Send / Import / Continue），内容与文案中文；主界面两个入口用中文「和 AI 聊聊」「导入试卷」。
- 题卡为"纸张"卡片：细边线、极浅阴影；AI 结果区使用浅绿底；每题对话窗为可折叠的内嵌区域，未展开时只显示一行提示与消息数。

### 7.2 信息架构

```
启动即进入（单用户，无登录）
  └─ 首页：学科宫格（语文 英语 历史 政治 地理 物理 化学 生物 数学）＋ 最近作答 ＋ 两个入口
       ├─ 「和 AI 聊聊」 → AI 对话页（内嵌 OpenCode Agent：流式输出 + 工具调用卡片 + 新对话）
       ├─ 「导入试卷」 → 直接选 JSON 文件（不走 AI）
       ├─ 学科试卷库：试卷卡片（来源徽章、题量、总分、进度）＋「同步文件夹」
       │    └─ 答题页
       └─ 记录（所有作答记录：试卷、时间、得分、模型）
设置：CLI 路径与自检、默认模型、Provider 账号、导出目录（= 放题目录）、超时、提示词预览
```

**放题目录（`~/Documents/问学试卷`）** 是双向的：Agent 出卷/导入时导出到这里，同时应用每次启动会自动扫描该目录（含学科子文件夹）里的 `*.json`，把尚未入库的试卷自动收录（按 `id` 与 `标题+总分+题量` 双重去重）。试卷库与设置页另有「同步文件夹」按钮可手动强制扫描。

### 7.3 答题页（核心）

- **顶栏**：返回｜试卷标题｜`Model` 下拉（可刷新）｜进度 `3/12`｜累计得分｜`Submit`（汇总出分）。
- **左侧目录**：题号列表，状态点：灰=未答、蓝=已答、绿=已批；点击滚动定位。
- **题卡结构**（每题独立）：
  1. 题头：`第 3 题 · 现代文阅读`｜`6 分`｜`已批 4.5`
  2. 阅读材料（**默认展开**，超过 210px 可点「收起」/「展开全文」）
  3. 题干；`choice` 渲染单选按钮，其余渲染 textarea
  4. 操作条：`Grade with AI` `Explain` `Ask AI (n)` `Clear`
  5. 批改结果：分数环 + 等级 + 总评 + 得分点/失分点/知识点/下一步
  6. **该题专属对话窗口**：只含本题消息；输入框 + `Send`；支持展开/折叠、消息数、按时间回溯；`Explain` 的结果也落在此窗口
- **自动保存**：输入 500ms 防抖写盘；切题、离开页面、关闭窗口均 flush。
- **一键汇总**：底部 `Submit` 计算已批/未批，给出总分与提示，写入 `summary`。

### 7.4 AI 对话（全局 Agent）

1. 首页点「和 AI 聊聊」或顶栏「对话」进入；顶部可选模型、可「新对话」；
2. 首次发消息时，主进程把「放题目录 + 试卷 JSON 格式契约 + 你的角色」拼成系统上下文随首条消息发给 OpenCode CLI，之后用 CLI 返回的真实 session id 续接；
3. Agent 每走一步（读文件、写试卷、跑命令）都会以 `tool` 事件推给界面，渲染成工具调用卡片；文本按 `full` 快照流式刷新；
4. 出卷时 Agent 直接把 `<放题目录>/<学科>/<日期>-<标题>.json` 写盘，应用启动/同步时自动收录入库；
5. 也可以纯聊天：讲题、诊断错因、定学习计划、改本地文件——说什么都行。

## 8. IPC 接口（preload 暴露）

```
cli:    detect, test, models
settings:get, settings/save, dialog/pickFolder
paper:  list, syncFolder, get, delete, import, export
agent:  chat（全局对话，runId + 流式事件）
dialog: pickFolder, pickFile / file: read
attempt:start, get, saveAnswer, setModel, finish, history
ai:     chat, grade, cancel
```
流式事件统一走 `ai:event`：`{ runId, paperId, questionId, stage, kind, text|tool|error, done }`。

安全：`contextIsolation: true`、`nodeIntegration: false`、`sandbox: false`（需调 IPC 的 preload 已足够）、外部链接走 `shell.openExternal` 白名单。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 免费模型额度/地区限制 | 批改失败 | 错误码翻译 + 引导配置 Provider 账号；模型下拉标注可用性 |
| `run` 文本非增量 | 等待感强 | 分阶段状态（理解题目→生成评语）＋ 工具事件实时展示 |
| AI 输出非严格 JSON | 解析失败 | 三层容错 + 原文降级 + 一键重试 |
| CLI 版本差异（参数变动） | 调用失败 | 版本探测 + 参数最小集（只用 `run/models/--session/--format/--model/--auto`） |
| 长材料导致上下文过大 | 变慢/超限 | 阅读材料默认展开（保证可读），但只在首条消息携带；跨题不共享正文 |
| 客观题用 AI 批改浪费额度 | 成本 | `choice` 本地比对答案，其余走 AI |

## 11. 打包与分发

```bash
npm run build:app              # 产出 /Applications/问学.app
OUT_DIR=dist npm run build:app # 产出到项目 dist/ 便于分发
```

做法（见 [build-app.sh](../scripts/build-app.sh)）：

1. 用 `cp -cR`（APFS clonefile）复制 `node_modules/electron/dist/Electron.app` 作为模板 —— 与模板共享磁盘块，**不额外占用 ~250MB**；
2. 删除 `Resources/default_app.asar`，写入 `Resources/app/{electron,renderer,prompts,package.json}`；
3. 改 `Info.plist` 的 `CFBundleName` / `CFBundleDisplayName` = 问学、`CFBundleIdentifier` = `com.wenxue.desktop`；
4. `codesign --force --deep --sign -` 做 ad-hoc 签名（本机可直接运行，无公证）。

要点：

- **不打进 OpenCode CLI**：.app 内只有前端与主进程代码，CLI 仍由 `opencode.detect()` 在运行时探测本机安装（桌面版内嵌路径 / PATH）。
- **数据目录保持一致**：`Resources/app/package.json` 的 `productName` 刻意保留 `Wenxue`，使打包版与开发版共用 `~/Library/Application Support/Wenxue`，历史试卷与作答记录无需迁移。
- 应用代码非 asar 打包（目录直读），便于排障；如需减小体积可后续加 asar。
